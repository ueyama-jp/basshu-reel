# BasShu Instagram 自動投稿

週3回(月・水・金)、動画とキャプションが自動でできあがり、
スタッフが確認画面で「投稿する」を押すとInstagramに投稿される仕組みです。
Woolly用の仕組みをもとに、BasShu専用に作り直したものです。

## 中身

| 場所 | 役割 | 動く場所 |
| --- | --- | --- |
| `gas/` | 頭脳。商品の読み込み、商品・素材選び、文章づくり、確認画面、投稿、通知 | Google(Apps Script) |
| `src/` | 動画づくり。注文を受け取り、写真3枚・12秒の縦型動画を書き出す | GitHub(Actions) |
| `assets/` | BGM(自作の4曲。投稿ごとに順番に使う)と、テスト用の仮画像 | |
| `docs/v/` | できた動画の置き場(GitHub Pagesで公開され、30日で自動的に消える) | |
| `test/` | Google側の代役を立てて全体を試すテスト | |

月額の費用は、文章づくりのAI利用料(ごくわずか)だけです。

## Woollyとの違い

- 素材フォルダは全商品ぶんは作らない。「商品」シートの「フォルダを作る」にチェックした商品だけ作る
- フォルダのない商品は、サイトの写真だけで投稿候補になる
- 「商品」シートの「次に投稿する」にチェックすると、その商品が次の回で最優先になる(使われたら自動で外れる)
- 直近と同じ分類(ラグ、ブランケットなど)が続かないように選ぶ
- 写真はすべて画面いっぱいに置く。サイトの商品写真は正方形なので、左右が切れる
- 柱は「商品紹介 → 季節の暮らし → 色と柄の話 → 育っていくもの → 商品紹介」
- 「育っていくもの」はサイトの写真だけで作る(AI生成の画像は使わない)
- 機能の言い切り(抗菌、消臭、空気清浄、安眠など)はAIに書かせず、投稿ボタンでも止める
- 文字は白で、うしろに半透明のグレーの下地を敷く。書体はゴシック体

## 設定の順番

1. GitHubに公開リポジトリ `basshu-reel` を作り、この一式を入れ、Pages(`main` ブランチの `/docs`)を有効にする
2. Googleで Apps Script を作り、`gas/` の3ファイルを貼り付けて `setup` を実行する
3. ウェブアプリとして公開し、URLと合言葉をGitHubの Secrets(`WEBAPP_URL`、`WEBAPP_KEY`)に入れる
4. スクリプト プロパティに `ANTHROPIC_API_KEY` と `IG_TOKEN` を入れ、`testAI`、`testInstagram` を実行する
5. `suggestScenePhotos` を「残り0件」と出るまでくり返し実行する(サイトの写真から、使用シーンの写真を選ぶ)
6. `makeNow` を実行して、最初の投稿候補を作る

## つまずきやすい点(Woollyで実際に起きたこと)

- GitHubには、フォルダごとではなく **フォルダの中身** を入れる。`basshu-reel` の中に `basshu-reel` ができたら入れ子になっている
- `.github` フォルダはドラッグでは入らない。GitHubの画面で「Add file」→「Create new file」を選び、
  名前を `.github/workflows/reel.yml` にして中身を貼り付ける
- Instagramの許可画面では、**「コンテンツへのアクセスと公開」がオンになっていること** を確かめてから進む。
  オフのままだと、投稿が権限エラーになる
- Apps Script のコードを差し替えたら、「デプロイ」→「デプロイを管理」→ 鉛筆 →「新バージョン」でデプロイし直す。
  保存しただけでは、確認画面と動画づくりには反映されない
- パスワード、合言葉、APIキー、Instagramのトークンは、各サービスの設定欄にだけ入れる。チャットや文書には貼らない

## BGM

- `assets` の中の、名前が `bgm_` で始まる曲を、名前の順に、投稿ごとに1曲ずつ使う
- 今は4曲: 1 落ち着いたギター → 2 ジャズ調のピアノ → 3 静かなピアノ → 4 ボサノヴァ調のギター
- 曲を足すときは、`bgm_` で始まる名前の `.m4a` を `assets` に入れるだけ。外すときはファイルを消す
- 権利の確認ができた曲だけを入れる

## 素材のきまり

- フォルダが要るのは、力を入れたい商品だけ。月に5〜10商品、1商品につき2〜3枚が目安
- 画像は JPEG か PNG(iPhoneの HEIC は対象外)。縦長(9:16)で入れる
- 動画は 30MB まで。使われるのは最初の約4秒。音は使わない
- 撮影した素材は、ファイル名を「実写」で始めると「イメージ画像」の札が付かない
- 使い込んだ姿(経年変化)は、AIで生成しない。実写かサイトの写真だけを使う
- 商品に紐づかない場面の素材は「季節の暮らし」フォルダに入れる

## 管理シートの「商品」でできること

| 列 | 使い方 |
| --- | --- |
| フォルダを作る | チェックすると、翌朝までにその商品の素材フォルダができる(すぐ作るなら `syncProducts` を実行) |
| 次に投稿する | チェックすると、次の回はその商品で作る。急ぐときは続けて `makeNow` を実行 |
| 季節 | 「春夏」「秋冬」「通年」。季節外の商品は選ばれない(い草は春夏、ウールは秋冬が初期値) |
| 使用シーンの写真番号 | サイトの写真のうち、動画の1枚目に使う写真の番号。AIが入れた番号を直せる。0 は「なし」 |
| 寄りの写真番号 | 動画の2枚目に使う写真の番号 |

## 手元で試す

```
python3 src/make_placeholders.py assets
node test/run.js                       # Google側の動きを確認
node test/server.js assets/任意の動画.mp4 &   # Google側の代役
WEBAPP_URL=http://127.0.0.1:8765/exec WEBAPP_KEY=(表示された合言葉) \
  PAGES_BASE=https://example.github.io/basshu-reel NO_GIT=1 python3 src/run_job.py
```
